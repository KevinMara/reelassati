# Structured script writing

Script generation keeps the existing `title`, `hook`, `body`, `cta` and `fullScript` fields and requests an optional `writingPack` in the same provider call and existing paid script action. No second generation, new provider, price change or automatic regeneration is introduced. The workflow is adapted from the recovered Ootto hook writer, reel scripter and reel builder guides; source URLs and the upstream MIT notice are in `docs/licenses/ootto-content-skills.md`.

The pack contains ten distinct spoken and on-screen opening options, ranked 1–10 with short editorial reasons; a table of narration, optional screen text, visual direction and planned start/end seconds; and two distinct alternate CTA phrasings. Rank means creative preference for the brief, never a measured performance score or a prediction of virality. The prompt retains the requested platform, duration, tone, language, audience and brand direction as input data, asks for original work, forbids invented evidence and unsupported promises, and treats references/brand notes as untrusted data rather than instructions.

`clock: "planned"` marks proposed writing timings. The table has 1–24 contiguous positive intervals, starts at zero and ends exactly at the requested 8–180-second script duration. Its joined narration must match the clean original `fullScript` apart from whitespace. These estimates must be retimed to recorded speech before timeline editing; they are not a transcript, observed reference timecodes or proof of an achievable speaking rate. The server attaches the original clean narration as `scriptText`, allowing the UI to show when subsequent script edits have made the generated plan stale while keeping the alternatives available.

Normalization rejects duplicate hooks, duplicate ranks, invalid row counts, incomplete/overlapping/reversed/nonfinite timings, mismatched narration, missing required text, duplicate CTAs and oversized content. Text fields and the entire normalized pack are bounded; unrecognized fields such as provider performance scores are omitted. Beat screen text may be empty. A missing or invalid pack is omitted whole, and the valid legacy script remains usable; the server does not fabricate missing options or silently repair timestamps.

The optional pack is included in the existing script provenance projection without changing legacy records that have no pack. Save/reload retain normalized structured outputs. A human edit to the pack uses existing derivative handling; storage tampering cannot retain the old signed badge. Workspace normalization removes malformed packs instead of preserving unchecked provider or browser JSON.

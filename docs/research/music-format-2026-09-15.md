# Music compatibility findings — 15 September 2026

The existing OpenRouter Lyria integration requested WAV and rejected any other codec. Current [Google generateContent music documentation](https://ai.google.dev/gemini-api/docs/generate-content/music-generation) explicitly lists `lyria-3-clip-preview` as a fixed 30-second MP3 output. The [OpenRouter model page](https://openrouter.ai/google/lyria-3-clip-preview/api) still describes older 48 kHz stereo output and $0.04 per clip. This establishes a compatibility gap; it does **not** establish the exact cause of the earlier failed production request.

`finishMusicAudio` now validates and preserves native WAV or MP3. WAV retains the existing exact PCM trim/fade. MP3 is trimmed only at complete trailing frame boundaries, without decoding/re-encoding and without removing any leading audio frames, preserving Layer III reservoir dependencies. Xing/Info frame counts, byte counts and seek tables are rewritten; recognized LAME gapless delay/padding and tag CRC are updated. Native MP3 trimming does not add a fade. Without gapless metadata, duration rounds upward by less than one MP3 frame. With recognized gapless metadata, decoded duration matches the requested interval.

SSE parsing now handles standard multiline events, ignores alternate completion choices instead of splicing songs together, exits at `[DONE]` without waiting for connection closure, and converts interrupted stream reads to safe typed errors. Documented non-stream JSON `message.audio.data` responses are also supported. Size limits remain enforced.

Verification: 14 targeted tests passed, including actual LAME-encoded MP3 fixtures, native codec detection, metadata/provenance round trips, complete-frame boundaries, corrupted/truncated input, JSON responses, multiline SSE, a connection remaining open after `[DONE]`, and stream interruption. VBRI coverage adds a standard metadata frame to the native CBR fixture, verifies the retained byte count and complete seek table, and rejects malformed table geometry. The native FFmpeg test decodes six trimmed files across Xing/LAME, CBR and VBRI at requested durations of 3.01 and 3.5 seconds; decoded sample counts match the returned duration within one output sample. Earlier native checks also covered 3 and 4 seconds. VBR with gapless metadata is exact; CBR and VBRI round upward to a complete MPEG frame.

Codec metadata behavior was checked against the [FFmpeg MP3 demuxer](https://ffmpeg.org/doxygen/trunk/mp3dec_8c_source.html) and locally encoded fixtures. LAME tag CRC uses the reflected CRC-16 polynomial, verified against the native fixture checksum. Native duration verification uses seekable files, because decoding an unseekable stdin stream cannot reliably apply final-packet gapless padding.

No paid provider call or API-key read was performed during this investigation. Production generation and playback still require a live test after the root agent integrates dynamic codec metadata and deploys.
